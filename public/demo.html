Chronos Billing Engine

Parcours guidé : de la consommation de ton API par un client jusqu'à sa facture.

L'API expose un seul endpoint métier : POST /api/v1/events. Un client externe (imagine une app qui consomme ton API météo) appelle cet endpoint à chaque fois qu'il utilise ton service. La règle de facturation codée dans BillingCalculator est simple : 1000 appels/mois inclus, puis 0,02 € par appel au-delà. Les 3 étapes ci-dessous suivent un appel du client jusqu'à la facture générée à partir des données réellement stockées en base.
1

Le client consomme ton API

Le bouton ci-dessous envoie N requêtes réelles POST /api/v1/events au serveur, une par "appel" simulé du client. Chaque requête porte une Idempotency-Key différente, générée côté navigateur, pour que le serveur les traite comme des événements distincts.

0
envoyés
0
acceptés (202)
0
refusés

Il y a aussi un rate-limiter configuré dans config/packages/rate_limiter.yaml : 200 requêtes/minute maximum, compté par adresse IP (pas par client_id — regarde EventController::__invoke(), la ligne $this->eventIngestionLimiter->create($request->getClientIp())). Avec 15 appels ci-dessus tu restes largement en dessous. Monte le champ "Nombre d'appels" à 220 et relance : les 200 premières requêtes passent en 202, les 20 suivantes basculent en 429 Too Many Requests — regarde le compteur "refusés" et le journal en dessous.

2

Le worker traite en tâche de fond

Ton serveur HTTP a déjà répondu 202 sans toucher la base — c'est le messenger-worker, un processus séparé, qui écrit réellement chaque événement, en vérifiant qu'il ne l'a jamais vu (idempotence).

Ouvre un terminal à côté et lance :

docker compose logs -f messenger-worker

Tu y verras chaque événement inséré en base quelques dizaines de millisecondes après l'étape 1 — la facturation est découplée du trafic entrant, donc ton API ne ralentit jamais à cause de la facturation.

3

Tu factures le client

En fin de mois (ou à la demande ici), tu additionnes tous les événements réellement enregistrés pour ce client et tu appliques la règle de tarification.
